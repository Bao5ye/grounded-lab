# 程序化扎根理论 Skill 使用手册

本 Skill 将 Grounded Lab 的研究流程用于支持 Skill 的大模型工作环境。您可以让模型协助整理研究意图、管理资料、开展程序化三级编码、复核人工编码、形成候选理论模型，并导出研究成果；每项解释最终由研究者判断。

**Skill 不需要填写大模型 API Key。** 分析和角色协调由调用 Skill 的宿主模型承担，随附 Python 脚本只负责本地项目管理、证据检查和导出，不调用模型接口。宿主本身的网络、账户、费用和数据处理方式取决于您使用的平台及其设置。

## 一、开始前

您需要：

1. 一个支持读取本 Skill 文件的工作环境，例如已配置 Skill 功能的 Codex。
2. Python 3.9 或更高版本。项目脚本使用 Python 标准库，无需单独安装其他 Python 软件包。
3. 宿主能够读取您提供的资料、运行本地脚本并写入项目目录。如果只能进行纯对话，模型可以协助讨论，但不能实际替您导入文件、持久保存项目或生成导出文件。
4. 取得资料使用授权。涉及访谈或观察记录时，请按照研究方案、知情同意和所在机构要求，决定是否脱敏、哪些资料可交给所用宿主模型处理。

不同平台对 Skill、子智能体、文件和工具的支持并不完全相同。本手册以 Codex 和本地文件为例。

## 二、安装 Skill

### 方式一：使用本仓库文件

1. 打开 [grounded-lab 仓库](https://github.com/Bao5ye/grounded-lab)，选择 **Code → Download ZIP** 并解压。
2. 找到解压目录下的 `skills/grounded-theory` 文件夹。请复制**整个文件夹**，包括 `SKILL.md`、`references`、`scripts` 和 `assets`。
3. 将其放入宿主的 Skill 目录。对于默认配置的 Codex，目标通常是：
   - Windows：`C:\Users\<用户名>\.codex\skills\grounded-theory`
   - macOS / Linux：`~/.codex/skills/grounded-theory`
4. 新建一个 Codex 会话，输入 `$grounded-theory` 并说明任务。若未被识别，检查目录层级，确认 `grounded-theory` 文件夹内直接包含 `SKILL.md`，再重新打开会话。

如果设置过自定义 `CODEX_HOME`，请使用该环境对应的 `skills` 目录。若目标目录已有同名 Skill，请先备份并核对版本，不要直接覆盖未保存的修改。

### 方式二：Windows PowerShell 示例

下载并解压仓库后，将第一行改为**实际解压目录**：

```powershell
$repoRoot = 'D:\Downloads\grounded-lab-main'
$source = Join-Path $repoRoot 'skills\grounded-theory'
$target = Join-Path $env:USERPROFILE '.codex\skills\grounded-theory'

if (-not (Test-Path -LiteralPath (Join-Path $source 'SKILL.md'))) {
    throw '未找到 SKILL.md，请检查 $repoRoot。'
}
if (Test-Path -LiteralPath $target) {
    throw '目标 Skill 已存在。请先备份并确认后再更新。'
}
New-Item -ItemType Directory -Force -Path (Split-Path -Parent $target) | Out-Null
Copy-Item -LiteralPath $source -Destination $target -Recurse
```

以上仅适用于默认 Codex 目录。安装后请在新会话中检查 Skill 是否可用。

## 三、第一次调用：先运行虚构示例

首次建议在对话中输入：

> 使用 $grounded-theory 创建一个独立的虚构示例项目，向我展示研究意图、原文片段、概念、范畴关系和候选核心范畴，并导出示例编码表与报告。请明确标注所有材料均为虚构。

模型应调用随附脚本复制示例项目，并告诉您项目和导出文件的位置。示例只用于学习操作；请为真实研究另建空白项目，避免将示例编码混入研究结果。

## 四、使用自己的资料

### 1. 交代研究意图并新建项目

可提供研究动机、研究问题、研究对象、分析单位、资料范围及已有认识。示例：

> 使用 $grounded-theory 新建一个名为“高校教师人智协作”的空白项目。研究问题是：教师如何在科研工作中调整与 AI 的分工？分析单位为一次协作事件。请先与我核对研究意图，并把项目保存在我指定的工作文件夹。

若您尚未明确全部字段，模型可先整理已有信息，再就影响分析的缺项向您询问。每个研究项目使用独立 JSON；不要把真实项目、访谈原文或备份保存在 Skill 安装目录或公开 GitHub 仓库中。

### 2. 提供并导入资料

告知模型文件的实际路径，或按宿主方式提供文件。可同时说明资料类型、参与者编号和纳入范围：

> 请将工作目录下的访谈稿 `P01.txt`、`P02.txt` 和观察记录 `observation.md` 导入当前项目。参与者分别标记为 P01、P02；观察记录标记为 P01。先展示资料清单、片段位置和纳入状态，不要开始编码。

- 直接导入 UTF-8 编码的 TXT、MD、CSV、TSV；CSV/TSV 按**纯文本**读取，不自动识别表格列。
- 单份文本文件上限 3 MB。脚本按空行分段，过长段落会拆分，并记录来源和字符位置；请检查拆分后的语境。
- PDF、DOCX、图片、音频、视频需要先使用宿主可用工具可靠提取、识别或转写。提取结果和来源定位应由研究者核对；随附脚本不直接解析这些格式。
- 每份新导入材料会保留完整文本及源文件 SHA-256。旧版项目中如果没有这些附加信息，不能据此补造原始文件。

### 3. 选择编码方式

**模型辅助编码：**

> 请以 $grounded-theory 对已纳入的访谈资料开展开放编码，逐段列出原文引文、概念、定义和编码理由。然后比较概念，提出子范畴、范畴及关系证据，最后形成候选核心范畴和理论故事线。所有结果先标为待审核，列出未处理或暂不编码的片段。

**人工编码：**

> 我将提供原文、概念名称和定义。请使用 $grounded-theory 将其记录到当前项目，并检查引文是否与关联原文逐字匹配。未经我同意，不要自行新增概念或确认结论。

**复核已有编码：**

> 请先独立阅读已纳入的原文，再对照当前编码，指出引文不匹配、概念定义不清、可能遗漏的含义、反例和替代解释。请将复核意见保存为备忘录，不要直接将编码改为已确认。

资料较多时，可要求模型分批处理并记录覆盖进度。模型应说明哪些片段已编码、已阅读但暂不编码、尚未处理；未读材料不能被描述为已经分析。

### 4. 开展研究者审核

请逐项查看概念名称、定义、原文引文、归属范畴及编码理由。您可以要求修改、补充、搁置或确认，例如：

> 请将 C-001 的名称改为“核查来源”，保留其原文关联，暂时不要确认。K-001 与 K-002 的关系缺少反例，请将这一缺口记录为理论抽样任务。

示例中的 C-001、K-001 和 K-002 只是示意；实际操作时请使用当前项目中显示的编码和范畴 ID。

确认某一项时请明确指出对象和判断，例如“我确认编码 C-001”或“我选择 X 作为当前核心范畴候选”。模型建议默认属于待审核状态；修改资料、编码、范畴或关系后，既有核心范畴确认会重新开放。

脚本检查引文是否存在于关联片段中，但**逐字匹配不证明编码解释正确**。关系和核心范畴也需要对照完整语境、反例和替代解释审阅。

### 5. 发展范畴与理论模型

主轴编码可围绕条件、情境、行动／互动、后果及范畴属性、维度展开；选择性编码可比较多个核心范畴候选并形成故事线。您可以这样要求：

> 请根据当前已记录的编码和证据，比较候选核心范畴，形成一版理论故事线和范畴关系图。对每条关系列出证据、反例或限定条件；缺少证据的关系标为待核验，不要推断为已证实。

导出的 Mermaid 图只呈现项目中已保存的范畴关系；模型需要结合证据和理论故事线解释图的含义。图形本身不证明因果关系或理论饱和。

### 6. 理论抽样、备忘录与饱和评估

可以要求模型记录比较备忘、研究者反思、反例和后续采集任务。好的抽样任务应包含：**尚不清楚的问题、补充采集的理由和具体追问**。

是否停止采集由研究者根据范畴发展、关系证据、新资料、反例和研究情境综合判断；编码数量、低新增率或任务完成不能单独证明理论饱和。

## 五、项目保存、续做与导出

### 保存与继续

项目以 JSON 文件保存。下次会话可指定现有文件：

> 使用 $grounded-theory 打开 `D:\research\my-project\project.json`，先检查项目、列出未审核编码和未处理片段，再继续分析。不要覆盖我的备份。

路径只是示例，请改成您自己的实际路径。建议每次重要修订或共享前另存 JSON 备份；避免多个会话同时修改同一个项目。

### 接续 Windows 应用项目

1. 在原 Windows 应用的“成果与导出”中导出项目 JSON。
2. 在 Skill 会话中提供该 JSON 的实际路径，要求先验证并复制到新的项目路径，再继续工作。
3. 脚本使用与原应用兼容的 `grounded-lab-v1` 格式。旧项目没有记录的资料覆盖状态、文件哈希或完整原始文件内容，不会被自动补造。

例如：

> 使用 $grounded-theory 验证这个 Windows 应用导出的项目备份，并复制为一个新项目后继续工作；请保留原备份。

### 导出成果

可以直接对模型说：

> 请将当前项目导出到一个新的成果文件夹，包含三级编码表、研究分析报告、范畴关系图和完整项目备份，并列出待审核或未覆盖的内容。

| 文件 | 用途 |
|---|---|
| `三级编码表.csv` | 概念、子范畴、范畴、核心范畴候选、引文、来源与状态，可用表格软件打开 |
| `研究分析报告.html` | 可在浏览器打开的项目报告，包含资料、编码、关系、备忘和操作记录 |
| `范畴关系图.mmd` | Mermaid 源文件，可在支持 Mermaid 的工具中渲染 |
| `项目备份.json` | 包含当前项目资料与过程记录的备份，可在本 Skill 中恢复 |

为避免误覆盖，导出目标中已有同名文件时脚本会停止；请使用新的成果目录。报告和备份可能含有完整访谈原文，分享或上传前应检查授权和脱敏情况。

## 六、角色分工与使用边界

模型可按资料处理、开放编码、主轴编码、理论整合、方法复核和研究者审核等角色组织工作。若宿主明确支持且您授权使用子智能体，可采用相应分工；否则由当前模型分阶段扮演角色。**同一模型的多个角色并不等于多个独立模型或独立研究者**，其一致意见不能直接当作编码信度。

本 Skill 是研究流程和本地工具，不提供原 Windows 应用的图形界面，也不保证所有宿主都能解析所有文件或运行子智能体。模型可能遗漏内容、误解语境或提出不受证据支持的关系；请保留原文、复核过程和研究者最终判断。

## 七、常见问题

**找不到 Skill？** 检查安装目录下是否直接有 `SKILL.md`，然后新建会话；自定义 `CODEX_HOME` 时检查对应路径。

**是否需要输入 API Key？** 使用 Skill 时不需要。仓库中原 Windows 应用的远程 AI 模式另有配置要求，两者是不同入口。

**为什么无法导入 Word 或 PDF？** 随附脚本只直接读取指定纯文本格式；请先用宿主可用工具提取文本，核对后再导入。

**为什么引文保存失败？** 请检查证据 ID 是否属于当前项目、引文是否与关联片段连续且逐字一致，包括标点和空格。

**能否恢复备份到已有文件？** 恢复命令拒绝覆盖已有目标。请恢复到新路径；需要替换原文件时，先独立备份并由研究者决定。

**技术操作和项目数据结构在哪里？** 请看 [项目操作参考](references/operations.md)、[研究流程与角色](references/workflow.md) 和 [Skill 定义](SKILL.md)。
