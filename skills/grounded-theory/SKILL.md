# 程序化扎根理论工作台

以当前会话可用的大模型完成分析与协调；不要要求或配置模型 API Key、调用本项目的远程模型接口，或通过脚本自行调用另一个模型。按用户意愿选择人工编码、模型辅助编码、复核既有编码或理论整合；人工模式不主动生成编码。研究者对概念、关系、核心范畴和停止采集作最终判断。

## 开始与保存

1. 确认研究目标、资料、分析单位、保存位置和用户选择的模式；根据现有信息先推进，只询问确实影响分析的缺项。未提供材料时提供意图卡和资料准备步骤，不编造资料。涉及敏感资料时按当前环境的数据访问和共享约束处理。
2. 使用用户指定的项目目录；未指定时在工作区创建有意义的项目子目录。**不要把真实项目数据写入 Skill 安装目录或发布仓库。** 每个项目使用独立 JSON，写入前保留现有数据。运行 `python <skill>/scripts/grounded.py --help` 查看命令。已有 Windows 版项目 JSON 可直接验证、备份和继续使用；恢复到已有路径前先保留副本并明确告知替换。
3. 可创建空白项目，或复制 `assets/example-project.json` 学习；其中的资料、编码和结论均为虚构示例，不能混入真实研究。TXT、MD、CSV、TSV 以 UTF-8 纯文本导入（CSV/TSV 不做列解析）。PDF、DOCX、音视频或图片须先经可用工具可靠提取或转写，保留来源定位并标明未核验处；不可假称原应用或本脚本支持自动解析。

## 分析与复核

阅读 [references/workflow.md](references/workflow.md) 获取角色、证据和结果要求；需要使用脚本时阅读 [references/operations.md](references/operations.md)。每个纳入的证据片段都要跟踪已读和未完成状态；上下文不足时分批处理、保存中间结果并向用户说明覆盖范围，不要声称已经分析未读资料。

- **开放编码：** 从资料逐字引文提出贴近语境的概念、定义、理由；一段可有多个概念，也可暂不编码。系统检查引文、证据与来源关联，文字匹配不等于解释正确。
- **主轴编码：** 比较事件、概念和情境，发展子范畴、范畴、属性、维度和有证据的候选关系，保留反例、限定条件及替代解释。
- **选择性编码：** 比较核心范畴候选，形成可修改的理论故事线、模型及适用边界；明确哪些关系缺证据。理论模型依据项目关系生成，不能凭图形替代证据。
- **方法复核：** 先独立阅读所覆盖资料并记录观察，再比较既有解释，提示遗漏、反例、抽样缺口和潜在过度解释。可用宿主明确支持且获授权的子智能体分工；否则由当前模型分阶段扮演角色，说明这不是独立模型或独立编码者，不能把角色一致误称为信度。
- **人工参与：** 人工新增、修订、补充和确认；模型建议以待审核状态记录。只有用户明确确认具体编码或核心范畴时才将其标记为研究者确认。备忘录、持续比较、抽样和饱和评估贯穿全过程；低新增率或任务完成不能自动证明饱和。

按照 operations 文档将结构化操作写入项目。引用原文须与关联证据逐字相符；来源、编码、范畴和关系变动会重新开放理论确认。未完成的步骤和操作记录须可追溯，保存的 JSON 不含 API Key。

## 交付

按用户要求导出三级编码 CSV、可独立打开的 HTML 研究报告、Mermaid 范畴关系图及完整项目 JSON。脚本输出的图仅表达项目中保存的关系；报告区分候选、已确认、搁置、反例及研究局限。说明实际覆盖率、未核验资料、缺口及模型和人工分工；不把虚构示例或待审核结论当成真实研究发现。
